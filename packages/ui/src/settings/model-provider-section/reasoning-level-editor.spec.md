# 模型推理档位编辑

## 行为

设置页里的推理档位给人看中文，存进配置的仍是模型接口要的英文值。聊天工具条和这里查同一张档位词表。

点「+」从固定词表加入一档：关闭、开启、极低、低、中、高、极高、最高、极致。已在列表里的项不可再加。词表没有的值走「其他」，手填原文。芯片显示中文；没有中文名的值显示原文。悬停能看到实际保存的字符串。顺序仍可拖动，从低到高由用户排列。

四个预设会替换整组档位，而不是追加：

- 开关：`disabled`、`enabled`
- 三档：`low`、`medium`、`high`
- 强度：`low`、`high`、`max`
- 完整：`minimal`、`low`、`medium`、`high`、`xhigh`

再次点中当前预设不产生新的覆盖。

## 映射

推理参数映射默认不展开。摘要说明这次请求会写入哪些字段。表达式只在「自定义映射」里编辑。

用户改档位时，只有当前还没有可用映射才写入模板。可用映射是个人草稿里的表达式；智能配置开启时，推荐映射也算。模板按供应商当前 API 格式选择，正文与内置目录里该格式的默认 `modelApiRules` 相同：

- Anthropic Messages：`thinking`、`output_config.effort`
- OpenAI Chat Completions：`reasoning_effort`、`reasoning.effort`、`thinking`
- OpenAI Responses：`reasoning.effort`

已有推荐或自定义映射时，改档位不改表达式。之后修改 API 格式，也不改写已经写入的映射。

智能配置匹配到的模型继续显示推荐档位和推荐映射。用户点选或套用预设后，档位成为个人覆盖；只有当时没有映射，才会同时写入模板。

## 所有者

- 档位列表与映射表达式：模型编辑草稿 `reasoningLevelValuesValue`、`reasoningLevelMapValue`
- 推荐档位与推荐映射：Host 的 Model Config Resolution
- 中文名称：`thoughtLevelLabels` 词表，聊天工具条与设置页共用

```text
点选或预设 → 草稿档位
           └─ 没有个人映射且没有推荐映射 → 按 API 格式写入模板
已有映射 → 只改档位
保存 → 沿用现有 Option Spec 提交
```

## 验收

- 新模型未匹配推荐时，可以用预设一次填上中文档位，并带上当前接口的映射模板
- 芯片显示中文，悬停能看到 `low` 这类原文
- 匹配到推荐配置时，档位直接显示推荐值的中文名，映射摘要使用推荐表达式
- 已有映射时，改档位或套用预设不会覆盖该表达式
- 自定义映射收起时仍能保存；表达式无效时展开编辑区
- 关闭、开启、低、中、高、极致等词条与聊天里的推理强度用词一致
